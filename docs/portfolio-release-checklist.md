# Portfolio mode and future public launch

This project is an independent portfolio prototype, not an authorized municipal service. The user's approved scope is a demonstration first, with a potential acquisition/public launch later. Technical checks are not legal clearance.

## Current demonstration

- Backend defaults to portfolio mode unless `PORTFOLIO_MODE=false`. Portfolio mode blocks mutations and private reads before session lookup. Public catalog/reviews do not expose community contributions; existing accounts, documents and database records are retained.
- Frontend defaults to portfolio mode unless built/started with `VITE_PORTFOLIO_MODE=false`. Both settings must agree. Do not set either false on a public demo. They are implementation switches for future reviewed work, not a launch checklist bypass.
- Login/registration and document upload screens show fictitious examples. No public demo credentials are needed. Stored account credentials have not changed.
- Sample itineraries/checklists use `tara_sibale_portfolio_state` in browser storage, separate from existing guest state. Clear demo preferences using the notice near the header. Never enter actual tourist details. Legacy local/account records are not deleted.
- Map controls display satellite, topographic, terrain and street imagery from the configured providers, with attribution. Routes and elevations remain sample information. GPX/offline navigation exports are unavailable. Guide-request controls show an explicit demo message and contact nobody.
- The local guide chat responds in page memory without sending prompts to the API in portfolio mode. No LLM provider is called.
- Catalog photos, galleries, available credits and the project's existing TaraSibale logo are displayed in portfolio mode. Licensed food images retain their credits and license links. Unverified emergency numbers and unsupported municipal authorship remain withheld from visible pages/exports.
- Runtime software notices are generated by `scripts/generate-third-party-notices.mjs` before frontend builds, and distributed as `THIRD_PARTY_NOTICES.txt`.

Preserving an asset in the archive is not permission to distribute it. Deploy only the built frontend and intended backend artifacts, not this repository, archive, credentials or PostgreSQL directory. For a public source release or buyer transfer, exclude unresolved assets or obtain permission first. Do not sell third-party copyrighted material as exclusively owned work.

## Before any real tourist/public launch

- [ ] Identify the legal operator and obtain municipal authorization before any official claim; clear brand/logo and source ownership.
- [ ] Complete an asset register with licenses, creator credits and retained written grants covering the intended commercial uses.
- [ ] Verify destination access, trail geometry, landowner permission, elevations, safety statements and emergency contacts with relevant authorities; record dates and responsible reviewers.
- [ ] Verify all ferry operators, schedules/fares and accommodation partnerships; define how stale information is removed.
- [ ] Establish booking/guide fulfillment, pricing, confirmation, refund/cancellation and complaints procedures before accepting reservations or payments.
- [ ] Complete operator-specific privacy notices, lawful-basis assessment, processor/hosting arrangements, retention/deletion and rights-request workflows, especially for IDs/documents. Determine applicable NPC registration/DPO requirements.
- [ ] Define contributor rights, moderation/reporting/removal and privacy/defamation handling before enabling public posts/reviews.
- [ ] Establish map-provider accounts/terms/attribution; audit actual final distributed software notices and dependencies.
- [ ] Provision a separate public/demo database containing only approved sample records; do not expose this developer database or existing personal records.
- [ ] Validate production HTTPS/session configuration, secret isolation, backups, access control, abuse protection and restore procedures.
- [ ] Obtain Philippine IP/privacy/commercial legal review of the actual final content, operator and acquisition terms.
- [ ] Only after separate authorization and readiness work, enable and test real account/booking/document functionality. Setting portfolio flags false alone is insufficient.

No policy text here claims to be a complete privacy policy or a guarantee against legal claims. Hosting, analytics and contact details must reflect the real deployment; there is currently no verified public operator/copyright-complaint contact configured.
